* **Chunk-boundary PII straddle: never split an atom, never emit on an unproven boundary**: The core leak vector chunking introduces: a PII value cut across a chunk boundary (jane.smith@example.com mid-token) matches no regex in either chunk, is never seen whole by the model, and verifies clean in both halves — a genuine regression vs whole-file processing. Trap: per-chunk three-layer pipelines look safe because every chunk gets the full treatment. Locked in the spec as two rules: (1) 'Never split an atom' — one line, one top-level JSON value, one YAML document, one TOML table; containers are descended into, never cut; an oversized atom refuses the run. (2) 'Never emit on an unproven boundary' — read a carry window before each chunk; a match touching either edge means widen and rescan; fail past a bound. Streaming never weakens verification: per-chunk gate + final rescan; run-scoped ledger (never on disk, never outlives the run) catches cross-chunk recognition. Input under budget keeps the single-call path byte-for-byte. Refuse rather than degrade: name reason, location, escape hatch.
